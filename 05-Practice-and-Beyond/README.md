# Module 05 — Practice & Beyond

> Patterns are a means, not an end. This module is about using them **wisely** — and knowing when
> *not* to.

## Contents

| # | Topic | One-liner |
|---|-------|-----------|
| 01 | [Anti-Patterns](01.Anti-Patterns.md) | Common traps (God object, singleton abuse, anemic domain model…) and their fixes |
| 02 | [Choosing a Pattern](02.Choosing-a-Pattern.md) | A selection guide + the classic "which one?" confusions |
| 03 | [Study Plan](03.Study-Plan.md) | An ordered roadmap + spaced-repetition checklist |

## After this module you can

- Smell an anti-pattern and refactor away from it.
- Pick the right pattern from a problem's signals — and resist over-engineering.
- Tell apart the lookalikes: State vs Strategy, Proxy vs Decorator, Factory Method vs Abstract Factory.
