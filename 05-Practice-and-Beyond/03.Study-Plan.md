# Study Plan: From Beginner to Pattern-Fluent

## 🧠 How to Use This

A concrete roadmap through the whole course, assuming ~1 hour a day. The **order** matters more than
the pace. The single most effective habit: for every pattern, **do the refactoring exercise before
reading the solution** — patterns only stick when you apply them to messy code yourself.

> 💡 Don't memorize 23 structures. Learn the *problem* each pattern solves and the *trade-offs*. In
> real work and interviews, you're judged on **recognizing** the right pattern and knowing **when not
> to use one** — not on reciting UML.

## 📅 The 5-Week Plan

### Week 1 — Foundations (do not skip)
- Read all of [Module 00](../00-Foundations/README.md): what patterns are + reading UML, OOP recap,
  **SOLID**, composition over inheritance.
- **Goal:** explain each SOLID principle with an example, and articulate why composition usually beats
  inheritance. Everything later builds on this.

### Week 2 — Creational
- [Module 01](../01-Creational/README.md): Factory Method → Singleton.
- **Goal:** replace scattered `new`/`if-type` creation with factories; build a fluent builder; use
  Singleton *correctly* (and know why DI usually replaces it).

### Week 3 — Structural
- [Module 02](../02-Structural/README.md): Adapter → Flyweight.
- **Focus:** the **Adapter/Facade/Decorator/Proxy** quartet — learn them *together* and nail the
  differences (a top interview topic). Do the [comparison table](02.Choosing-a-Pattern.md).
- **Goal:** tell the four structural lookalikes apart by intent.

### Week 4 — Behavioral
- [Module 03](../03-Behavioral/README.md): start with **Strategy** and **Observer** (most used), then
  the rest.
- **Focus:** **Strategy vs State** and **Strategy vs Template Method**.
- **Goal:** use Strategy/Observer fluently; implement undo with Command/Memento.

### Week 5 — Modern, Anti-Patterns & Synthesis
- [Module 04](../04-Modern-and-Enterprise/README.md): DI, Repository/UoW, CQRS, Null Object,
  Specification — the patterns you'll use most in real back-end work.
- [Anti-Patterns](01.Anti-Patterns.md) and [Choosing a Pattern](02.Choosing-a-Pattern.md).
- Drill the [Interview Cheat Sheet](../INTERVIEW_CHEATSHEET.md).
- **Goal:** wire up DI; recognize anti-patterns; map any problem to a candidate pattern (or to "no
  pattern needed").

## 🛠️ The Most Important Habit: Refactor Real Code

Patterns are learned by **transforming bad code into good code**. For each pattern:
1. Read the 🎯 **The Problem** section (the painful "before").
2. Cover the solution; try to refactor it yourself.
3. Compare with the worked solution; note what you missed.
4. Then find a smelly spot in *your own* projects that fits — and refactor it.

## ✅ Readiness Signals

You're fluent when you can:
- Hear a problem and name **2–3 candidate patterns** (and reject the wrong lookalikes).
- Explain any pattern's **trade-offs** and when *not* to use it.
- Connect patterns to **[SOLID](../00-Foundations/03.SOLID-Principles.md)** (e.g. "Strategy enables
  OCP", "Adapter/DI realize DIP").
- Refactor an `if-type` conditional into [Strategy](../03-Behavioral/01.Strategy.md), or a telescoping
  constructor into [Builder](../01-Creational/03.Builder.md), on the spot.
- Recognize **anti-patterns** and resist **Pattern Fever**.

## 🧭 Shorter Tracks

- **One weekend (crash):** [Foundations/SOLID](../00-Foundations/03.SOLID-Principles.md) + the
  [Cheat Sheet](../INTERVIEW_CHEATSHEET.md) + [Choosing a Pattern](02.Choosing-a-Pattern.md).
- **Interview in 3 days:** Strategy, Observer, Factory Method, Singleton, Decorator, Command + the
  lookalike comparisons + "when not to use a pattern."

## 🔜 What's Next (toward senior)

Patterns are the bridge from "writing classes" to "designing systems." After this, the natural
progression is **architecture & system design**: Clean/Hexagonal architecture, Domain-Driven Design,
microservices vs monolith, event-driven systems, and the rest of the senior-developer roadmap
(testing, databases, concurrency, DevOps, observability, security).
