# Module 00 — Foundations

> The "why" behind every pattern. Skip this and patterns feel like arbitrary rituals.

Design patterns are *applications* of a few deeper principles. Once you internalize SOLID and
"favor composition over inheritance," most patterns become the obvious thing to do.

## Contents

| # | Topic | One-liner |
|---|-------|-----------|
| 01 | [What Are Design Patterns](01.What-Are-Design-Patterns.md) | What/why, the 3 categories, how to read a UML class diagram |
| 02 | [OOP Recap](02.OOP-Recap.md) | Encapsulation, abstraction, inheritance, polymorphism; interface vs abstract class |
| 03 | [SOLID Principles](03.SOLID-Principles.md) | The five principles, each with a bad→good refactor |
| 04 | [Composition & Principles](04.Composition-and-Principles.md) | Composition over inheritance, program to an interface, DRY/KISS/YAGNI |

## After this module you can

- Read a UML class diagram and the relationships it shows.
- Name and apply each SOLID principle, and spot violations.
- Explain *why* composition usually beats inheritance.
