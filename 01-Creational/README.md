# Module 01 — Creational Patterns

> *How objects are made.* These patterns make object creation flexible, decoupled, and intentional.

The problem they all attack: scattering `new` everywhere hard-wires your code to concrete classes.
Creational patterns put that decision in one controllable place.

## Contents (in learning order)

| # | Pattern | Intent |
|---|---------|--------|
| 01 | [Factory Method](01.Factory-Method.md) | Let subclasses decide which class to instantiate |
| 02 | [Abstract Factory](02.Abstract-Factory.md) | Create **families** of related objects |
| 03 | [Builder](03.Builder.md) | Construct complex objects step by step (fluent APIs) |
| 04 | [Prototype](04.Prototype.md) | Create new objects by cloning existing ones |
| 05 | [Singleton](05.Singleton.md) | One instance, global access — and its many pitfalls |

## After this module you can

- Replace scattered `new` calls with a factory and explain the benefit.
- Build a fluent builder for an object with many optional parts.
- Use Singleton *correctly* — and know when it's an anti-pattern.
