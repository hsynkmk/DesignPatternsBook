# Module 02 — Structural Patterns

> *How objects are composed.* These patterns assemble objects and classes into larger structures
> while keeping them flexible.

The first four — **Adapter, Facade, Decorator, Proxy** — look similar and are constantly confused
in interviews. Learning them together (and their differences) is high-value.

## Contents (in learning order)

| # | Pattern | Intent |
|---|---------|--------|
| 01 | [Adapter](01.Adapter.md) | Make an incompatible interface usable |
| 02 | [Facade](02.Facade.md) | A simple interface over a complex subsystem |
| 03 | [Decorator](03.Decorator.md) | Add behavior dynamically by wrapping |
| 04 | [Proxy](04.Proxy.md) | A stand-in that controls access (lazy, caching, remote) |
| 05 | [Composite](05.Composite.md) | Treat individual objects and groups uniformly (trees) |
| 06 | [Bridge](06.Bridge.md) | Decouple an abstraction from its implementation |
| 07 | [Flyweight](07.Flyweight.md) | Share fine-grained objects to save memory |

## After this module you can

- Tell **Adapter vs Decorator vs Proxy vs Facade** apart by their *intent*.
- Model tree-shaped data with Composite.
- Recognize when wrapping (Decorator/Proxy) beats subclassing.
